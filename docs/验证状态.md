## 3. 已知脚本问题

1. `scripts/production-check.mjs` 调用 `browser-v03.mjs`；后者仍断言首页有八个时期，当前实际为九个，因此在首段断言失败。本次生产服务HTML、封面及非法API输入检查已执行到，但整条生产回归没有通过，也未完成后续全部场景检查。
2. `scripts/browser-new-era.mjs` 在点击返回后立即断言Canvas为零，没有等待React路由更新。数字敦煌在此处失败；独立重复三次检查均观察到点击后立即还有一个Canvas，等待卸载后为零。不能将这次脚本失败表述为通过，也没有证据据此认定场景持续泄漏。
3. CI当前只执行锁定安装、单元测试和构建，不运行浏览器脚本。浏览器专项成功不能由CI绿色状态推断。

本轮仅修改文档，上述脚本问题仍待修复。日志：`artifacts-review-production.log`、`artifacts-review-new-era.log`；离场复核：`artifacts/review/departure-check.json`。

## 4. 可复现命令

基础检查：

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm dev
```

浏览器检查另需Playwright模块和已安装的Microsoft Edge，仓库当前未将Playwright列入开发依赖。可自行安装开发依赖，或使用已有模块的绝对路径作为脚本第一个参数。以下命令假设 `playwright` 能由脚本解析，且开发服务已运行：

```sh
node --import tsx scripts/browser-eras.mjs
# 使用已有模块时，将实际绝对路径作为最后一个参数
node --import tsx scripts/browser-eras.mjs /absolute/path/to/playwright
```

生产模式下可单独运行新增切片回归，须先build并保持生产服务运行。以下是执行方法，不代表本次已经跑完这一组生产回归。

macOS/Linux：

```sh
# 终端一
PORT=5174 pnpm start
# 终端二
BASE_URL=http://127.0.0.1:5174 node --import tsx scripts/browser-eras.mjs
```

Windows PowerShell：

```powershell
# 终端一
$env:PORT = '5174'
pnpm start
# 终端二
$env:BASE_URL = 'http://127.0.0.1:5174'
node --import tsx scripts/browser-eras.mjs
```

生产服务启动后可访问 `/api/status` 检查配置状态。模型已配置时，脚本中的问答可能调用真实供应商，其回答与引用不一定满足为预置模式编写的断言；预置流程回归与真实模型评测应分别记录。无配置时为preset模式。

# “文化切片”需求说明 v0.10.1

更新日期：2026-09-30。本文说明当前版本的产品范围与验收条件。历次扩展目标、旧数量及制作补记保留在[整理前快照](archive/需求说明_整理前快照.md)和[迭代记录](迭代记录.md)，实际验证结果见[验证状态](验证状态.md)。

## 1. 产品定位与目标

面向大学生与文化爱好者，用可以观察、操作和追问的三维微缩场景，将器物、技术与文化知识放回具体生活情境。一个切片围绕一个主要问题展开；历史分组用于导航，不将并存政权解释为简单继承，也不将历史变化一概解释为“后来的更好”。

当前交付为桌面网页参赛原型。用户通过浏览、器物操作、预置讲解或可配置的 AI 自由问答了解文化线索。模型、建筑组合、动画及合成声音属于教学性艺术表现，不等同于遗址测绘、文物扫描或历史现场复原。

待验证的产品目标是：用户能否主动探索，器物操作是否帮助理解，情境问答是否承接好奇心。工程可运行不能代替用户学习效果验收。

## 2. 当前内容范围

九个历史阅读分组，每组三景，共 **27 个可玩场景、193 个观察入口、81 个核心操作步骤、76 条去重资料出处**。观察入口包括器物与生活空间；核心步骤按已登记、可持久保存的动作计数，不包含点火等临时演示。数字依据 `catalog.ts`、`content.ts` 与各期 `exhibits*.ts`，分组明细见[全时代补齐进度](全时代补齐进度.md)。

- 裴李岗生活村落：六个区域、十个观察入口；核心流程为放入谷物、磨粮两个持久步骤，另有点火、泥条成形、住居展开等临时演示。
- 其余 26 个切片：共有 183 个观察入口、79 个有序操作步骤。高铁有八个入口，其余各七个；汉代织机为四步，其余为三步。
- 史前至近现代的八个分组已经制作，新时代新增复兴号与高铁站台、天宫空间站、数字敦煌：采集与共享。全部目录项均可进入，没有待制作占位项。

### 新时代的说明边界

- 高铁：首尾两节驾驶车与四节中间客车，共六节教学展示编组；供电、气流和站内缓行是示意，不作为真实车型编组或运营速度的证据。
- 天宫：表达 2022 年三舱 T 字基本构型，省略来访飞船等内容；设备、数据与动作示意，不是实时遥测或当前全貌。
- 数字敦煌：表达分区摄影、图像拼接与公众展示流程，使用自绘练习图，不冒充敦煌原作或 AI 自动修复成果。

## 3. 用户流程与核心功能

时间轴 → 进入场景 → 观察对象 → 尝试操作 → 提问或查阅资料 → 探索回顾 → 返回时间轴。

### 时间轴与导航

- 九个分组分别包含日常生活、生产技术、精神文化三类切片；使用本项目场景渲染图作为封面。
- 桌面支持时期按钮、横向滚动、方向键和 Home / End；窄窗口采用纵向列表与单列卡片。
- 哈希路由支持直接链接、刷新及浏览器前进后退；“继续探索”恢复最后进入场景的稳定进度。
- 首页只加载二维界面与封面。进入体验页后加载三维模块，同一时间只运行一个场景。

### 观察与操作

- 悬停名称、高亮、相机聚焦、旋转与缩放用于观察对象；常规画面不显示常驻物件标签。
- 裴李岗支持村落、区域、器物三级浏览；其他切片提供全景与对象聚焦，室内对象按场景展开遮挡屋顶或墙体。
- 核心操作具有顺序约束，完成后才记录进度；新增切片支持取消、跳过、重放、回顾与当前场景重置。
- 裴李岗磨粮支持拖动、左右方向键和自动演示，放料完成前不能加工。点火与制陶示意不计为核心操作完成。
- DOM 按钮提供键盘与触屏入口；动画尊重减少动态设置。离场释放动画、声音及未完成的客户端问答请求。

### 情境问答与资料

- 服务端按登记标识读取当前场景、选中对象、已完成步骤、人工整理的资料摘要、演绎边界与有限对话历史。
- 模型用于生成讲解与交流，不控制场景动作或判断操作结果；当前不读取实时画面，也不自动检索网页或向量库。
- 未配置模型时保留预置讲解，并明确自由问答未连接；未知问题不冒充模型生成回答。
- 请求期间显示等待；失败可以重试，错误不破坏探索进度。
- 回答可提供登记资料入口；引用标识存在不等于事实正确，内容仍需人工核验。

### 进度与恢复

- 各场景独立保存已进入、已观察和已完成操作；临时动画与完整聊天记录不写入浏览器存储。
- 重新开始只清除当前场景进度；旧对象 ID、步骤 ID 和进度键继续兼容。
- 损坏或不兼容存储回到有效初始状态，不能恢复跳步或跨场景动作。

## 4. 环境与非功能要求

- 推荐 Node.js 24、pnpm 11.19.0，以及支持 WebGL 2 的桌面 Chrome 或 Edge。其他设备的兼容性须独立记录。
- 本地开发与生产服务默认监听 `127.0.0.1:5173`；运行及模型配置方法见[README](../README.md)。
- 全部生产静态资源的 gzip 估算以 10 MB 为预算；这是资源体积预算，不是首屏实际传输量，也不表示本地 HTTP 服务自动启用压缩。
- 登记设备上以稳定 30 FPS 为目标。短时 rAF 回调间隔不等于 GPU 帧时间，不能据此推定低配或长时间运行达标。
- WebGL 不可用时保留静态说明、对象按钮、资料及基础操作入口。
- 模型凭据由服务端读取，不进入前端或版本控制；公开模型状态仅说明配置是否完整，不证明服务实际连通。
- 建筑、器物与场地须体现具体时期、地域和用途；制作前登记依据，资料不足处标注推定。标准见[场景建筑与地形规范](场景建筑与地形规范.md)。

## 5. 验收条件与当前边界

### 工程验收

覆盖九个分组与 27 个入口、路由导航、观察与操作、顺序约束、取消与重放、旧进度兼容、回顾与重置、预置讲解、接口校验、引用过滤、错误重试、390px 布局、减少动态、WebGL 降级及离场清理。真实指针命中和视觉质量需要浏览器检查，不能仅用单元测试代替。

2026-09-30 的验证范围和已知脚本问题见[验证状态](验证状态.md)。其中新增 26 景的完整回归为开发模式；不将其表述为当前全部场景的生产模式验收。

### 真实模型与内容验收

配置真实模型后执行[AI 核查案例](AI核查案例.md)及分期内容核查问题，保存实际回答、模型配置、上下文、依据、人工判断和修订结果。事实正确、引用支撑、指代消解、错误前提纠正与资料不足处理分别记录。已有少量 DeepSeek 个案记录不能代替系统评测或专业史料审读。

### 目标用户验收

邀请五名大学生或文化爱好者，不预先教学操作。至少四人独立完成核心互动，并解释工具关系及一个有依据的知识点；记录完成率、求助情况和反馈。若未达到，优先修订内容与交互，再安排扩展。当前仓库没有该验收的完成结果，不据场景数量推断学习成效。
